# Couleurs des caractéristiques, compétences et postures

Les caractéristiques, leurs compétences et les postures ont chacune leur couleur (demande du propriétaire), les attributs aussi (santé rouge, barrière jaune, chakra bleu, corruption noire).

Principe (demande du propriétaire du 2026-10-22) : « Partout il faut utiliser Que les couleurs du site. Si le site n'a pas de règle il ajoute une nouvelle couleur au site en se basant sur celle du classeur. Aucune couleur en dur. » ; pour le texte, « Privilégé la lisibilité. » (`sort-format.mjs#texteSurCouleur`). Une couleur se lit dans le module de sa règle, jamais recopiée dans un CSS ou un rendu ; une couleur ajoutée ne double pas une règle qui existe.
Source des couleurs (réponse du propriétaire du 2026-10-22) : « La classe CSS du site qui va avec la couleur de base, comme pour les magies. Si elle n'existe pas, créer une classe CSS avec la couleur du classeur. »

## Palette en classes (`client/src/lib/palette-css.mjs`)
- Une classe `.couleur-<famille>-<id>` par couleur des règles : `--couleur` (fond : la couleur de la règle passée par `alchimie-couleurs.mjs#lisible`, inchangée sauf Loyal Bon et Loyal Neutre, à peine éclaircis pour atteindre 4,5:1, testé) et `--couleur-texte` (`texteSurCouleur`). Fabriquée au build depuis les modules des règles. Le module n'écrit aucun hex.
- Émission (choix de conception du lot 3, 2026-10-22 : toutes les familles sur chaque page dépasseraient le plafond de 4 ko) : `FAMILLES_DE_CHAQUE_PAGE` (magie, attribut, caracteristique, affinite) et les seconds rangs des magies sont posés sur chaque page par `layouts/Base.astro` (`cssDeLaPalette`, un `<style is:inline>` à part, après `cssDesAttributs()` ; environ 3,4 ko, épinglé sous 4 ko) ; `FAMILLES_DES_ZONES` (posture, alignement) et les seconds rangs des caractéristiques ne sont émis que par le composant des pages qui les posent (`cssDesFamilles([...])`, `cssDesSecondsRangs(famille)`) : le bloc `postures` de `GuideBloc.astro` (postures), `pages/fiche/index.astro` (postures et alignements), `ArmesPage.astro` (seconds rangs des caractéristiques). Une page qui pose une classe d'une zone émet sa feuille : `site-html` vérifie que chaque classe posée existe dans une feuille de la page.
- Deux magies sur un même élément (choix de conception du lot des magies, 2026-10-22) : la première est la classe de sa magie ; la seconde, sa classe de second rang `.couleur-2-magie-<id>` (`classeDeSecondeMagie`, `secondsRangsDesMagies`, `secondsRangs(famille)`), qui ne pose que `--couleur-2`, de la même valeur. De même pour une arme de deux compétences (R48) : `classesDeDeuxCaracteristiques(premiere, seconde)` → classe de la première caractéristique et `.couleur-2-caracteristique-<id>` de la seconde, ou de la même. Un élément qui peut en avoir deux porte toujours les deux (`classesDeDeuxMagies(premiere, seconde)`, la seconde = la première s'il n'y en a qu'une) : rien n'est hérité d'un parent. Sert aux cadres de la fiche, aux lignes de `/personnages/`, aux créatures (bouton d'un sort, choix de la fiche), aux cibles de défense du bestiaire, aux traits de la carte de `/magies/` (le survol fait lire `--couleur` ou `--couleur-2` selon la magie survolée : `seconde-<magie>`). `classesDeLaPalette()` : toutes les classes posées sur chaque page (tests) ; `couleursDeLaPalette(familles)` : toutes, ou celles des familles demandées.
- Familles (`FAMILLES_DE_LA_PALETTE`) : `magie` (`sort-format.mjs#COULEURS_DES_MAGIES`, id = nom court normalisé : `feu`, `espace-temps` ; plus `par-defaut` = `COULEUR_PAR_DEFAUT`), `attribut`, `caracteristique` (plus `par-defaut` = `COULEUR_NEUTRE`), `affinite` (les dix `COULEURS_DES_AFFINITES`, source : Doc « Alchimie »), `posture` (clé = fin de l'id de la base ; plus `par-defaut`), `alignement` (`Loyal Bon` → `loyal-bon` ; plus `par-defaut`). Id = la clé du module passée par `text.mjs#normalize` (`chakra+sante` → `chakra-sante`), stable quand le nom affiché change. Un neutre (couleur d'un id inconnu) est la classe `par-defaut` de sa famille, jamais un hex de repli.
- Noms : `classeDeCouleur(famille, cle)`, `classeDeMagie(nom)`, `classeDAttribut(cle)`, `classeDeCaracteristique(id)` (celle d'une compétence : sa caractéristique ; `par-defaut` si inconnue ou absente), `classeDePosture(id ou clé)`, `classeDAlignement(nom)` (`par-defaut` si inconnus), `classeDAffinite(id)` (via `alchimie-couleurs.mjs#baseDAffinite`).
- Couleurs calculées : `couleurDePotion` rend `{ fond, texte, base: { famille, cle }, niveau }` ; `classeDePotion` → `couleur-potion-<famille>-<id>-n<rang>` (`--ligne-fond`, `--ligne-texte`) ; `cssDesPotions(couleurs)` n'émet que les combinaisons demandées (la page qui les affiche : skill `zone-ceinture`).
- Exception (réponse du propriétaire du 2026-10-22 à « Ce noir ou ce blanc de mélange compte-t-il comme une « couleur en dur » ? » : « Non, exception (Recommandé) » ; option : « Le noir et le blanc purs servant à assombrir ou éclaircir restent écrits ; l'exception est notée dans la règle des couleurs du site. ») : `#000`, `#fff`, `#000000`, `#ffffff` comme argument d'un `color-mix(…)` (liseré de `.acc-gemme`, `equipement.css`). Rien d'autre ; un test qui contrôle les couleurs écrites tolère exactement cela (`test/palette-css.test.mjs#couleursEcrites` : hex, fonctions de couleur dont un argument est écrit hors `var(…)`, couleurs nommées d'une feuille ; une teinte écrite dans une variable, `--gh: 5`, ne s'y voit pas).
- Ajouter une couleur : l'écrire dans le module de sa règle (une famille nouvelle : l'ajouter à `FAMILLES_DE_LA_PALETTE`) ; la page pose la classe, sa feuille lit `var(--couleur)`.
- Ne pas importer `palette-css.mjs` dans un script de page (`src/scripts/`), ni dans un module qu'un script de page importe (`personnages-liste.mjs`) : il tire tous les modules des règles. Un script de page reçoit les noms des classes de sa page (`data-couleurs` de `/personnages/` : `[classe, classe de second rang]` par magie) ou de `regles.json` (`classe`, `classe_2` de chaque magie ; `classe` de chaque caractéristique, posture et alignement, `caracteristique_par_defaut`, `alignement_par_defaut`) et les pose par `classList`, jamais une couleur. `ceinture-rendu.mjs`, `monstre-rendu.mjs`, `composants-rendu.mjs`, `armes-rendu.mjs` l'importent ; ils passent dans l'éditeur du site de dev (`edition-rendu.mjs`, `scripts/edition/races.mjs` aussi), hors version portable, et dans les modules livrés du service (`test/serveur-livraison.test.mjs`).

## Choix du propriétaire (2026-10-22, questions de cadrage)
- « Module JS → classe » : la valeur reste dans le module de sa règle, la feuille des classes en est fabriquée au build, les pages ne posent plus que la classe.
- « Thème reste, Debug à part » : les variables du thème (`styles/global/base.css`) restent la règle du thème, toute copie ailleurs passe par elles ; la page Debug et l'impression ne changent pas.
- « Règle de calcul » : la base est une classe du site, la nuance se calcule depuis elle, une classe par combinaison seulement là où une page en a besoin, sans couleur écrite.
- « Garder séparées » : chaque couleur garde son nom et sa classe (changer la santé ne change pas la catégorie Mêlée) ; mais une affinité qui est un attribut ou une magie reste la classe de cet attribut ou de cette magie (pas de recopie).
- Lots : l'onglet Ceinture (potions, bâtons) est passé aux classes (lot 1) ; puis toutes les couleurs des magies (lot 2 : pages et carte des magies, races, classes, guide, bestiaire, composants, accessoires, fiche, personnages) ; puis les caractéristiques et leurs compétences, les postures et les alignements (lot 3 : guide, cartes du bestiaire, compétence des armes et leur filtre, métiers et leur éditeur, fiche ; repli de la compétence inconnue d'un métier `#8a7a66` et replis `#fff` des cartes des caractéristiques, des tableaux des compétences et de l'alignement retirés). Restent en style, pour les lots suivants : matériaux, poids et types d'armure, paliers de résistance (`--r` de `fiche.css`), catégories de classe, races et ethnies, parties du guide (`--etape`, `--guide`, `--couleur-partie`), niveaux des accessoires, Mode Hyper et Cent pour cent de la fiche (`.posture-carte--hyper`, `--cent` : pas des postures), chronologie, livres, neutres de la fiche hors lot 3 (`#6b5a45` d'un groupe de races, `#8a7a66` d'une ethnie, de la magie acquise « Aucune » et d'un objet de départ, dans `scripts/fiche.mjs`) et le repli `#fff` des pastilles `.pastille` et `.choix__pastille` (`fiche.css` : ne sert plus qu'aux races, ethnies, classes et objets de départ ; `HORS_DU_LOT` de `test/palette-css.test.mjs`), texte blanc des bannières (`.magie-hero` de `magie/page.css`, `.race-hero`, `.classe-hero`), teintes des genres de sort (`.genre` de `magie/sorts.css` : `--gh`, `hsl(…)`) et des types de don (`classe/dons.css`), ombre de l'infobulle partagée (`.bulle` de `global/infobulles.css`, règle qui lit `--mag` exclue du contrôle : `HORS_DU_LOT`). L'impression ne change pas (choix « Thème reste, Debug à part »).
- Une feuille garde ses variables locales (`--mag`, `--mag-texte`, `--creature-1`, `--cadre`, `--magie-1`, `--c` de la fiche…) mais les tire des propriétés de la classe (`var(--couleur)`, `var(--couleur-2)`), jamais d'un style. Dans la fiche, `teinte-palette` (avec la classe d'une magie, d'une caractéristique, d'une posture ou d'un alignement) fait lire `--c`, `--c-texte`, `--texte-sur-c` dans la classe (`fiche.css`, `fiche.mjs#teinteDe`, `poserTeinte`) ; dans le guide, `.guide-carac`, `.guide-competences__groupe` et `.guide-posture` tirent `--c` et `--c-texte` de la classe (`guide/blocs.css`).
- La carte de `/magies/` calcule encore, au build, la part de la couleur dans un trait d'après sa luminance (`MagiesConstellation.astro`, `couleurDeMagie`) : un calcul, pas un rendu ; la couleur rendue vient de la classe.

## Invariants
- Posées par leur classe (`couleur-caracteristique-<id>`, `couleur-posture-<id>`, `couleur-alignement-<id>`), jamais en style : aplat clair, texte foncé (un alignement foncé : texte blanc). Guide, bestiaire, armes, métiers, fiche.
- Une compétence a la couleur (la classe) de sa caractéristique.
- La fiche les reçoit par `regles.json` (`fiche-regles.mjs` : `classe` de chaque caractéristique, posture, alignement ; plus de `couleur` ni de `texte`) ; son script (`src/scripts/fiche.mjs`) n'importe ni le module ni la palette.
- Un id inconnu reçoit `COULEUR_NEUTRE`, soit la classe `par-defaut` de sa famille.
- Attributs : une seule source (`attributs-couleurs.mjs`) ; `fiche.css` et `bestiaire/carte.css` lisent `var(--attribut-<clé>)` et n'écrivent aucune de ces couleurs.
- Lisibilité d'une ligne colorée : texte de `texteSurCouleur`, contraste d'au moins 4,5:1 (`lib/alchimie-couleurs.mjs#lisible`, pour les potions ; chaque classe de la palette l'atteint déjà : testé).
- Une feuille lit les propriétés qu'émet la palette (`--couleur`, `--couleur-texte`, `--couleur-2`, et `--ligne-fond` / `--ligne-texte` des combinaisons) : `ceinture.css` (`.batons-table tr.baton`), `equipement.css` (`.acc-gemme`), `tableaux.css` (`tr.ligne-couleur`), et les règles des magies (`magie/base.css`, `potentiel.css`, `tableaux.css`, `creatures.css`, `global/pastille.css`, `bestiaire/carte.css`, `composants.css`, `race/page.css`, `classe/page.css`, `guide/blocs.css`, `accessoires.css`, `fiche.css`, `personnages/liste.css`), et celles du lot 3 (`guide/blocs.css` : `.guide-carac`, `.guide-competences__groupe`, `.guide-posture` ; `bestiaire/carte.css` : `.bcarac` ; `armes/armes.css` : `.arme-comp` ; `metier/tableau.css` : `.metier-cible, .metier-carac` ; `fiche.css` par `teinte-palette`), épinglées par `test/palette-css.test.mjs` ; un renommage se fait des deux côtés.
- Une base de potion sans couleur dans sa règle n'est pas une base (`baseAvecCouleur`) : la ligne reste neutre.
- Palette : la valeur de chaque classe est celle de sa règle ; aucune classe ne recopie une autre règle ; une page ne pose que la classe, jamais un style de couleur (là où son lot est fait) ; sur toute page construite, aucune couleur de magie, de caractéristique, de posture ni d'alignement en style (ni `--c-texte`, `--texte-sur-c`, `--c1`, `--c2` dans un `style`) et chaque classe `couleur-…` posée existe (`test/site-html.test.mjs`).
