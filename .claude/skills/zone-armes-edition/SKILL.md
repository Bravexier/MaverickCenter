# Armes : édition sur le site de dev

Fichiers : service `serveur/edition-armes.mjs`, extension `src/scripts/edition/armes.mjs`. La page : skill `zone-armes`. Mode modification commun, refus et sources de maîtrise d'une famille : skill `zone-edition` (« Familles d'armes »). À lire : `docs/content-guide.md`, « Armes », puces « Mode modification » et « Familles d'armes » ; `docs/serveur.md`, « Édition des règles (site de dev) ».

## Mode modification
- Les onglets restent affichés (demande du propriétaire : « Je veux les onglets aussi », qui remplace pour l'affichage en onglets la demande antérieure « Quand le mode Edition est lancé, il n'est pas possible de "sélectionner" une arme / matériau / amélioration, mais tous les tableaux sont visibles ») : un panneau ouvert par menu ; aucune règle `body.ed-mode` ne cache les barres ni ne montre les panneaux fermés ; le titre de la famille ouverte (nom, dé, compte) se montre et porte ses champs. Pas de sélection.
- Tout se modifie sauf les matériaux, en lecture (leur seule source est la page Composants, R62 ; skill `zone-composants`), et les armes élémentaires, en lecture (R167 : ni champ ni bouton Supprimer ; la raison et les colonnes d'une amélioration d'arme qui se modifient : skill `zone-edition`).
- Une arme se crée et se supprime (R52) : ligne `htmlDeLigneDArme` (la même pour la page construite et l'éditeur), ajoutée à la fin des armes du tableau de sa famille, avant ses armes élémentaires, et du corps Markdown ; son onglet de famille s'ouvre et la page défile jusqu'à elle. Supprimée, elle quitte les fiches (`serveur/fiches-retraits.mjs#RETRAITS`, note datée ; skill `zone-fiches-base`). Sa famille peut être « @i » (créée par l'opération i du même lot).
- Le nom d'un matériau d'arme est `ressource.nom` (partagé) : renommé, il change aussi dans les cases des tableaux des pages Armures et Bouclier (`corpsAvecMateriauRenomme`), pas dans les noms d'armures composés.

## Familles d'armes (R159)
Demande du propriétaire : « la possibilité de changer le nom et leur dés, ou même de créer un nouvel onglet donc un nouveau tableau si besoin ».
- Affichage : le nom (`data-ed` du nom du titre, `attributsNom`), le dé (pastille du titre, toujours écrite, `data-ed-cadre`, cachée si vide) et l'en-tête de coût (`<span data-ed>` dans l'en-tête `ed-seul` de la colonne) se modifient dans l'en-tête du tableau, jamais dans l'onglet, qui suit en `data-ed-lecture` ; ARME DE MONSTRES reste hors de la page.
- « + Nouvelle famille » (`.armes-nouvelle-famille`) juste après la barre de chaque menu, hors du tablist : la catégorie est celle du menu (`data-armes-bloc`), jamais changée ensuite ; formulaire nom, dé, en-tête de coût (`ENTITES.arme_famille` sans la catégorie) ; un refus 400 ou 409 s'affiche tel quel.
- Après création : l'onglet et le tableau vide insérés à chaud depuis les deux `<template data-armes-modele="onglet|famille">` de la fin de la page Armes (rendus par `OngletDeFamille` et `TableauArmes` pour `MODELE_DE_FAMILLE`, jetons `__id__`…, ids uniques ; posés là où l'éditeur peut se charger, comme `Edition.astro` : jamais dans la version portable, `INLINE_CSS=1`, mais dans le build de production ; remplis par `htmlDeFamilleDepuisModele`, test d'égalité avec chaque famille construite), la barre rebranchée (`onglets:brancher`, ré-entrant), l'onglet ouvert, la famille ajoutée à `ed.listes.famillesDArmes`, puis `armes:rafraichir`.
- La surcouche dessine les familles créées (`en-attente`, `creee`) avant leurs armes ; une famille enregistrée met à jour le dé de l'onglet, `data-unite` et la liste ; `fin()` retire les boutons. Le middleware ne rend pas les balises d'un `<template>` (`{{solidite}}`) : le site de dev les rend une fois posées (`mots-cles-vivants.mjs`).
- Données (`serveur/edition-armes.mjs#ARME_FAMILLE`, `TABLES.arme_famille`, `ENTITES.arme_famille`) :
  - modifiables : `nom`, `de_brut` (forme `edition-modele.mjs#DE_DE_FAMILLE`, remis en majuscules sans espaces), `cout_libelle` (`COUTS_DE_FAMILLE`, les trois de l'import) ; `libelle_brut` refait (`corps-armes.mjs#libelleDeFamille` : « NOM - dé » + la note d'après le dé) ; jamais `id`, `categorie`, `nom_lecture`, `maitrisable`, `ordre` ; ARME DE MONSTRES refusée (400, R45) ;
  - le dé d'une famille dont la note écrit des dés selon la Force (PUGILAT : `desSelonLaForce(note_brut)` non vide) est refusé (400 : limite technique, la fiche lit les paliers de la note, pas `de_brut` ; le message cite les paliers par `armes-de-famille.mjs#texteDesDesSelonLaForce`) ; son nom et son en-tête de coût sont permis ; un renommage ne change pas la note ;
  - création (nom, dé, catégorie `contact`/`distance` de `CATEGORIES_DE_FAMILLE`, en-tête) : id `normalize(nom)` (suffixe par `idDejaEmploye`), `ordre` max + 1, `maitrisable = 1`, `nom_lecture = nom`, `origine = 'equipement'`, `source_ref` du site, une ligne `page_entite` ; pas de suppression ;
  - corps : section titrée par le bandeau échappé (`titreDeSectionDeFamille`, comparaison exacte), en-tête `enteteDeFamille` ; une famille créée a sa section à la fin du corps (les sections des familles sont les dernières : `corps-armes.test.mjs`) ; renommée, le titre et sa puce des armes de départ ; `arme_famille` passe avant `arme` dans `TABLES_DE_LA_PAGE_DES_ARMES`, et au rejeu une famille créée avant une renommée (`recalculerLesPages`) ;
  - `chargerArmes` garde les familles sans arme (une famille créée a son onglet dès sa création ; seules les non maîtrisables restent hors de la page, R45) ; `listes().famillesDArmes` donne `{ valeur, libelle, categorie }` ;
  - le classeur exporté garde sa grille fixe de 11 familles (`fiche-tableur-cases.mjs#MAITRISES`) : les dés d'une famille créée ne vont dans aucune ligne, un avertissement le dit (`avertissementDeFamilleHorsDeLaGrille`) ; l'import lit une famille par son nom ou son nom de lecture.
