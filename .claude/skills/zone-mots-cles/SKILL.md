## Le glossaire (table `mot_cle`)
- Migrations `0043`, `0056` (`0058` : « Solidité »), `0090` (R183 : Lexique converti), `0098` (`couleur`, `url`), `0110` (`verrou`). Colonnes : `id` figé, `libelle`, `libelle_cle` = `normalize`, `description` (la définition), `abreviation` (une par mot-clé, NULL sinon), `couleur` et `url` (NULL sinon), `verrou` (0 ou 1, `DEFAULT 0`).
- La définition est NULL tant qu'elle n'est pas écrite, partout ; elle se lit `?? ''`.
- Une page porte un mot-clé par `page_tag.tag_id` (`ON DELETE CASCADE`) ; un sort, en étiquette, par `sort_mot_cle` (migration 0067, sans cascade : R114 ; « Sort fer » sur les 13 sorts « Fer… », migration 0079 : R164).
- Un mot-clé renommé garde son id (et ses adresses `?mot-cle=<id>`) ; une page créée par le service ne reçoit que des mots-clés protégés.
- Une abréviation peut valoir l'id de son propre mot-clé (`rf`, `ro`, `pp`, ids de la table `monnaie`). « CR » est l'abréviation de `corruption` (R183 (3)), `cr` n'existe plus. Les étiquettes protégées s'appellent « Classe » et « Métier » (R183 (8)).

## Balises
- Marquage explicite seulement, jamais de repérage automatique (demande du propriétaire). `{{ref}}`, `{{ref|texte}}` (gras, définition en infobulle), `{{ref:}}` (mode complet « **Libellé** : définition »). Dans une case de tableau Markdown, `\|`.
- Dans une saisie, `ref` = id, écriture ou abréviation du mot-clé, sans égard à la casse ; la casse écrite est gardée (`{{solidité}}` → `{{solidite|solidité}}`, `texteEcrit` ; demande du propriétaire). Une abréviation s'enregistre telle que la base l'écrit : `{{Cr}}` → `{{corruption|CR}}`, `{{AM}}` → `{{armure-magique|AM}}` (R183 (2) ; R140).
- La base ne garde que des ids, sous la forme canonique de la colonne (`typeDeTexte`, `CHAMPS_DE_TEXTE` de `lib/edition-modele.mjs`, la seule liste des types de champ texte) :
  - texte mis en forme (Markdown : pages, chronologie, panneaux) : `{{id}}` (suit le libellé ; le libellé écrit en texte y revient), `{{id|texte}}` pour un autre texte, `{{id:}}` ; une balise dans un code (`zonesDeCode`) est gardée telle quelle ;
  - texte de case (`ligne`, `texte`) : `{{id|texte}}` toujours (il se lit sans le vocabulaire) ; le mode complet est refusé.
- Le service enregistre la forme canonique (`texteAvecMotsClesCanoniques`, avant les dérivations et le journal). Il refuse une ref inconnue ou ambiguë (deux mots-clés visés par deux des trois chemins, id, écriture, abréviation : `ambiguiteDe`), sauf si elle était déjà présente avant, et le mode complet dans un texte de case.
- Fusionner recible les balises (sauf refus de R222 (1), plus bas), dans les colonnes texte de `TABLES`, par le chemin normal d'une modification (`reecrireLesBalises`). Supprimer n'en réécrit aucune, sauf en forçant (R223, plus bas) ; renommer non plus.
- Un emplacement `{N}` n'est jamais `{{N}}`.

## Rendu (middleware)
- Rendues dans les nœuds de texte, une bulle par mot-clé et par page. Jamais dans script, style, textarea, template, code, pre, kbd, samp, svg, math, ni sous `[data-mots-cles-bruts]` (`/donnees/`, aides, dialogues du mode modification, page Debug), ni dans leurs attributs. `EXCLUS` : même liste dans `mots-cles-vivants.mjs`.
- Un mot-clé à adresse est un lien `a.mot-cle`, son `url` préfixée de la base du site (`import.meta.env.BASE_URL` au middleware, `ed.base` sur le site de dev), sans `tabindex` ; sans adresse, `strong.mot-cle`. Dans `SANS_LIEN` (a, button, summary, label, select) ou une `.bulle` : le gras seul, sans bulle dans un bouton ou un résumé ; un `[tabindex]` garde le lien. Un mot-clé coloré porte sa classe sur sa balise, le bloc du mode complet et sa bulle (skill `zone-mots-cles-liens`).
- Texte simple dans `<title>`, `<option>` et les attributs de texte (sauf `data-balise`, `data-ed…`).
- « (classe) » (R191) : hors de `PAGES_AU_LIBELLE_ENTIER` (Glossaire, Recherche, Données et ses sous-pages), le libellé perd son suffixe partout (balise, tuile, bulle, attributs, `<option>`, `PiedDePage.astro`), sauf la rubrique « Mots-clés » des notes de version (`/mise-a-jour/`, libellé brut hors middleware, sinon « Orios » et « Orios (classe) » fusionnent) : `mots-cles-balises.mjs#libelleAffiche`, `libelleEntierSur` ; page lue par `middleware.mjs#optionsDeLaPage`, `mots-cles-vivants.mjs#libelleEntierIci`. `libelleEntier` : faux au rendu HTML, vrai dans `texteSansBalises`.
- Le titre d'une bulle est `htmlDuNomDuMotCle` : « Libellé (ABR) » ; une monnaie, son libellé et son icône (reconnue à son id de la table `monnaie`, jamais à son abréviation). Texte d'une balise, mode complet et bulle montrent les monnaies en icônes (`htmlAvecMonnaies`, décomposition comprise : R63, R183 (9), (12)). L'id `mot-cle-<id>` est réservé aux bulles (skill `ui-infobulles`).
- Un JSON servi retire lui-même les balises (`texteSansBalises` : `regles.json`, index de recherche) ; `page_fts` aussi (skill `base-sqlite`). Un découpage lit le texte sans balises ; un affichage morceau par morceau les garde (`avecLeursBalises`).

## Invariants
- `db:check` refuse une ref qui n'est pas un id et une forme non canonique (la règle de `formeCanonique`, sauf `{{id|Libellé}}` dans un texte mis en forme), dans toutes les colonnes de texte des règles et des pages (`lib/mots-cles-db.mjs#textesDeLaBase`, `formesNonCanoniques`), sauf les sections 13 à 15, les tables dérivées et les traces gardées telles quelles (`lib/tables-de-la-base.mjs`).
- `db:check` et le service refusent une abréviation qui rendrait une ref ambiguë (`fautesDeLAbreviation`, `docs/content-guide.md` ; égaler son propre id est permis) ; `abreviationsPrises` : un mot-clé créé ou renommé ne prend pas l'id ni l'écriture qui est l'abréviation d'un autre.
- Aucun script de page n'importe `mots-cles-balises.mjs` (il entraîne `text.mjs` et `monnaies.mjs`).
- Le sens d'une modification (R29, `lib/notes-de-version-sens.mjs`) se lit sans balises (`texteSansBalises`).

## Vocabulaire : ce que le service refuse
- Verrou (`mot_cle.verrou`, migration 0110 ; R218 à R222) : 1 pour les mots-clés à adresse, `rf`, `ro`, `pp`, ceux de `MOTS_CLES_PROTEGES` et celui d'une race, d'une magie ou d'une classe. Le service refuse en 409 (`serveur/edition.mjs#raisonDuGel`, `RAISON_DU_VERROU`) toute modification, quel que soit le champ, et la suppression, même sans mention ; `verifierNonVerrouille` refuse la fusion depuis lui. Il se pose encore sur une page, se cite par une balise et reçoit une fusion, sans reprendre l'adresse ni la couleur de la source. Aucune route n'écrit `verrou` : il ne change que par migration (R218 (4)). Création : 0, même avec une adresse (R219 (5)), sauf `race-hybride` : 1 (R220 (2)), au rejeu aussi ; le rejeu ne le contrôle pas (skill `zone-edition-rejeu`). Le mot-clé d'une race, d'une magie ou d'une classe est celui dont `url = '/'||id||'/'`, jamais celui du même id (une classe raciale `<x>-classe` en partage un). Test : `serveur-edition-verrou`.
- Fusion et texte gelé (R222 (1)) : la définition d'un mot-clé verrouillé n'est jamais réécrite. Une fusion dont la source est citée par une balise de la définition d'un verrouillé, celle de la cible comprise, est refusée en 409 avant toute écriture, avec la liste de ces mots-clés (`fusionner`). Cite : une balise `{{…}}` qui désigne la source, par id, libellé ou abréviation ; un mot sans balise ne cite pas. Ailleurs, la fusion recible comme avant. Le rejeu reste libre.
- Page visée par un mot-clé verrouillé (R221) : elle ne se supprime pas sur le site (`refuserSiUnMotCleYMene`, garde des liens rompus) et l'adresse du mot-clé n'est jamais vidée ; sinon la garde de la page décide (skill `zone-mots-cles-liens`).
- `MOTS_CLES_PROTEGES` identifie, ne refuse plus : ceux dont le site se sert pour ranger ses pages (catégories de `/classes/`, « classe », « race », « race hybride », « capacité de classe », « métier », « codex »), « Sort grenade » (R114) et « Sort fer » (R164), que la fiche lit. Reconnus à leur id, jamais à leur écriture (R195 : `mots-cles-r195` lève le verrou dans sa copie). Une page porte ses mots-clés par id en `data.mots_cles`, posé par `lib/wiki.ts` (`pages-db.mjs#motsClesDesPages`), jamais dans le `.md`.
- Un mot-clé qui étiquette un sort ne se supprime ni ne se fusionne (`409` qui nomme les sorts : `edition-chronologie.mjs#verifierSansSort`, `serveur-edition-chronologie.test.mjs`, R114, R164).
- Un mot-clé ne se supprime que si rien ne le mentionne (R196 ; `lib/mentions-des-mots-cles.mjs#mentionsDe`, `mentionsDesMotsCles`) : 409 avec `mentions` (page, ou table et ligne). Est une mention l'étiquette d'une page (`page_tag`) et une balise qui le cite par son id, son libellé ou son abréviation dans un texte de la base (`textesDeLaBase`), pages d'exemple comprises. Ne le sont pas : le code qui s'en sert, sa propre définition, son adresse, sa couleur, ni un prix « 100 RO », qui écrit l'abréviation sans balise. La fusion reporte les mentions sur la cible. Test : `mentions-des-mots-cles`.
- Suppression forcée (R223, amende R196 pour les non verrouillés) : `forcer:true` sur `supprimer` de `mot_cle` (`MOT_CLE.supprimer`, `refusDuForcage`). Sans lui, R196 est inchangée (409, `mentions`, `refus_du_forcage`). Avec lui, 409 avant toute écriture, dans cet ordre : le verrou ; le sort étiqueté ; une définition d'un mot-clé verrouillé qui le cite (`mots_cles_verrouilles`, comme R222) ; une adresse qui mène sans ancre à une page de la base (`pageDeLAdresse`, hors exemples ; `url` et `page` ; R223 (7), suppression de la page reportée) ; une mention que le site ne réécrit pas (`mentions_bloquantes`). Le critère est la page en base, pas `ADRESSES_FIXES` : une ancre, une route sans page (`/fiche/`) ou une rubrique (`/races/`) disparaît avec le mot-clé. Puis chaque balise devient « le texte affiché » (réponse du propriétaire ; `mots-cles-balises.mjs#texteQuiRemplaceLaBalise`, fonction pure) : `{{x}}` et `{{x:}}` le libellé, `{{x|texte}}` son texte, échappé en Markdown et en ligne de tableau ; une balise en tête de ligne reçoit `echapperDebutDeLigne` (`mots-cles-balises.mjs`, d'où `markdown-edition.mjs` l'importe : pas d'import circulaire), par `remplacerParLeTexteAffiche`. Les étiquettes de page sont retirées ; un contrôle final vérifie que `mentionsDe` est vide (sinon 409, lot annulé). `GET /api/edition/mots-cles/` donne `refus_du_forcage` (`refusDesForcages`). Un `forcer` posé hors d'un mot-clé rend 400, au service comme à l'API v1. Rejeu : skill `zone-edition-rejeu`. Tests : `mots-cles-r223`, `serveur-edition-suppression-forcee`.
- Renommer vers une écriture prise : fusion explicite (`fusionner_mots_cles`).
- L'abréviation : `serveur/edition.mjs#refuserLAbreviation` (création, renommage, changement) applique la règle de `db:check` : 400 si elle est mal écrite, 409 si un autre mot-clé la prend (`mot_cle` le nomme) ; le détail porte `champ: 'abreviation'`. Adresse et couleur : skill `zone-mots-cles-liens`.

## Importeurs
- Le `tags:` d'une page s'écrit par libellé : `tools/db/maverick.py#mot_cle` retrouve le mot-clé par son écriture d'abord (aller-retour `db:export-pages` / `db:sync-pages`). Un protégé se pose par son id : `maverick.py#libelle_protege` (`MOTS_CLES_PROTEGES` Python comparée à celle de JS par `mots-cles-python.test.mjs`), `codex.py` `Vocabulaire.protege`, `races.py`, `relations-races.py` (`--vocabulaire`) ; `serveur/edition.mjs#motCleDe`, de même.
- Un import ne crée jamais de mot-clé : une écriture inconnue n'est pas posée, `db:sync-pages` la signale (skill `sources-codex` pour `codex.py --vocabulaire`).
- Le site de dev est la source du vocabulaire (`historique_modification`) : une écriture quittée mène au mot-clé renommé ou fusionné ; celle d'un mot-clé supprimé n'est pas reposée (`poser_les_mots_cles`, `mots-cles-python.test.mjs`).
- Un import ne pose jamais un homonyme (`homonymes.py#MAGIES_HOMONYMES` : la magie « corruption » ou « sang » d'un temple du Codex, d'une page de magie, d'une créature invoquée) ni les étiquettes de `homonymes.py#ETIQUETTES_NON_POSEES` (R183 (11), R187 ; `importeurs-etiquettes.test.mjs`).

## Rejeu du journal
- Un lot d'avant la 0056 ou la 0043 (mot-clé libre, étiquette d'un mot-clé absent et non protégé…) est rejoué sans effet ni conflit (`ancienneEcritureDuGlossaire`, `sansEffet` ; `docs/serveur.md`). Balises d'un mot-clé supprimé ou fusionné, lots d'avant la 0090 et la 0098 : skill `zone-edition-rejeu`.
